Multi-talker ASR with LLMs

A WavLM-encoder + LLaMA-decoder speech recognition system for overlapped multi-speaker audio, trained with Serialized Output Training (SOT) and optional Serialized CTC supervision.

1. Overview

The system reads a single mixed audio waveform containing N overlapping speakers and produces a single text stream containing all transcriptions concatenated, separated by a special <sc> token. A WavLM encoder turns audio into acoustic features; an optional separator head splits those features into N per-speaker streams supervised by per-speaker CTC heads; a LLaMA decoder generates the serialized text autoregressively. Hybrid training combines attention CE loss on the LLaMA decoder with CTC loss on the separator heads.

Datasets supported

  • LibriMix 2-speaker (libri2mix)
  • LibriMix 3-speaker (libri3mix)
  • Clean and noisy variants

LLM backends

  • LLaMA-3.2-1B / 3B
  • LLaMA-3.2-1B-Instruct / 3B-Instruct
  • LLaMA-3.1-8B / 8B-Instruct

2. End-to-end pipeline

The full workflow is driven by run.sh (or run_librispeechmix.sh) and divided into six stages selected with stage=X stop_stage=Y.

1

Data preparation

Script: utils/generate_dataset.py  ·  Output: datasets/libri{N}mix_*/

Walks the LibriMix folder, builds an HF DatasetDict with audio, text, id, and prompt fields per sample. The prompt defaults to “TRANSCRIBE THE PROVIDED AUDIO INTO ACCURATE TEXT”.

2

Pretrained AED assembly

Script: utils/create_from_pretrained.py  ·  Output: dump/<encoder>-<decoder>/

Combines a WavLM encoder (microsoft/wavlm-large) with a LLaMA decoder into a SpeechEncoderDecoderModelLlama. Adds special tokens (<bos_prompt>, <eos_prompt>, <bos_speech>, <eos_speech>, <bos_response>, <eos_response>, <sc>), wires up the per-speaker CTC heads, separator, and writes the initial checkpoint.

3

Fine-tuning

Script: finetune_asr.py  ·  Launch: torch.distributed.launch --nproc_per_node=$NGPU

Loads the pretrained AED + dataset, runs preprocessing through vectorized_dataset_utils.preprocess_and_filter, applies LoRA via insert_adapter_decoder.insert_adapters, freezes/unfreezes selected params via unfreeze_utils.unfreeze_selected_params, and trains with a custom Seq2SeqTrainer that supports per-head CTC + optional PCGrad. Saves the final model and (if LoRA is used) merges adapters with utils/merge_adapter.py.

4

Inference (attention decoder)

Script: inference_asr.py  ·  WER: utils/compute-wer.py

Loads the fine-tuned model, runs autoregressive generation over the eval / test splits sample-by-sample, writes {split}_label.text and {split}_decod.text, then computes WER.

5

CTC-only decoding

Script: inference_asr.py --ctc_decoding=true

Decodes directly from the per-speaker CTC heads (greedy / argmax with blank+dup removal) instead of the attention decoder. Useful for ablation against the hybrid output.

6

Multi-GPU inference / pseudo-label generation

Script: inference_asr_gpus.py

Distributed eval: shards the eval set across GPUs (Dataset.shard), writes per-rank output files, and merges them on rank 0. Used to produce decoded outputs for the train set as pseudo-labels for downstream experiments.

3. Model architecture

The model is a SpeechEncoderDecoderModelLlama with three computational paths: encoder, separator + CTC heads, and decoder.

4. Training data flow

From a single audio sample to a backward pass:

1

generate_dataset.py emits each row as {id, audio, text, prompt}.

↓
2

vectorized_dataset_utils.preprocess_and_filter converts audio → input_values via feature_extractor, builds labels = tokenizer(prompt_str + input_str).input_ids, stores prompt_ids and prompt_token_len. Filters by duration.

↓
3

DataCollatorSpeechSeq2SeqWithPadding pads input_values, strips the leading <bos> from labels, builds decoder_input_ids (shift-right equivalent), appends an EOS sentinel, then sets labels[i, :prompt_token_len[i]] = -100 per sample.

↓
4

Seq2SeqTrainer.training_step forwards through the model: encoder → (optional separator + CTC) → decoder. The model prepends speech_len of -100 to labels to align with the post-speech-insertion decoder logits.

↓
5

HybridLoss computes loss_attn = CE(logits, labels), loss_ctc = mean over heads of mean-over-batch CTC, and combines as α·loss_attn + (1-α)·loss_ctc.

↓
6

Trainer optionally projects CTC head gradients via PCGrad before accelerator.backward(loss), clips, steps optimizer + LR scheduler, logs.

5. Inference data flow

1

Eval split loaded from datasets/{corpus}/{validation,test} via load_from_disk.

↓
2

For each sample: feature_extractor(audio) → input_features on GPU; tokenizer(prompt_str)[1:] → prompt_ids.

↓
3

Either model.generate(inputs=input_features, prompt_ids=prompt_ids, max_length=150, num_beams=1) (attention decoder, custom GenerationMixin_Instruct in utils/generation_utils.py) or model.generate_ctc(...) for CTC-only decoding (GenerationMixin_CTC in utils/generation_ctc_utils.py).

↓
4

Decoded text post-processed: special-token filtering, EOS trim, write to {split}_decod.text alongside {split}_label.text.

↓
5

utils/compute-wer.py computes per-utterance and corpus-level WER, writes {split}_decod.wer.

6. Training modes

The train_mode flag selects which loss is active:

ModeActive lossWhat trainsTypical use
attentionCE onlyDecoder + adapters + projectionPure SOT baseline
ctcCTC onlyEncoder + separator + CTC headsPretrain separator before LLM fine-tune
hybridα·CE + (1-α)·CTCEverything trainableMain training recipe

The α mixing weight is config.ctc_alpha (default 0.7 in HybridLoss), passed at construction in modeling_speech_encoder_decoder_llama.py.

Freeze policy when train_mode=ctc

In CTC mode, finetune_asr.py freezes the entire model, then unfreeze_selected_params enables only the encoder/separator/CTC components (no LoRA insertion). In hybrid/attention mode, LoRA is injected via insert_adapters and additional partial-unfreeze rules apply.

7. Cross-attention adapter variants

When decoder_cross_attention=true, an adapter module is inserted into each decoder layer that cross-attends to the encoder's acoustic memory between self-attention and FFN. The variant is selected by decoder_cross_attention_type:

TypeModuleBehavior
tinyTinyCrossAttnAdapter Plain Q/K/V projection + LN(hidden + cross(hidden, mem)). No gate.
gatetinyGatedTinyCrossAttnAdapter Tiny + scalar sigmoid gate, init -2 (≈0.12). Mixes refined and original hidden states.
adapgatetinyAdapGatedTinyCrossAttnAdapter Gated + adaptive-rank LoRA on Q / KV / Out projections. Controlled by r_max and lora_alpha.
ctcawareCTCAwareTinyCrossAttnAdapter Tiny + injects CTC-confidence as both log-bias on scores and multiplicative reweight after softmax.

The decoder_cross_attention_feature flag chooses what's used as the cross-attention memory:

  • raw — concatenated WavLM features (the same as the regular encoder output).
  • sep — concatenated per-talker separator features (gives the decoder per-speaker information).

10. Run recipes

End-to-end on LibriMix-2mix-clean, 1B LLaMA, hybrid SOT+CTC

bash run.sh \
  stage=1 stop_stage=4 \
  corpus=libri2mix_clean \
  talker_numbers=2 \
  encoder=wavlm decoder=Llama-3.2-1B \
  instruct=false \
  talker_ctc=true talker_ctc_refine=false \
  train_mode=hybrid \
  adapter_only_decoder=true \
  encoder_freeze=true decoder_freeze=true \
  partial_encoder_unfreeze="adapter" partial_decoder_unfreeze="" partial_others_unfreeze="enc_to_dec_proj" \
  separator_hidden=896 \
  per_device_train_batch_size=8 per_device_eval_batch_size=8 \
  epoch=30 eval_steps=1600 \
  precision=bf16 \
  ctc_bridge=false ctc_bridge_type=raw \
  decoder_cross_attention=false decoder_cross_attention_type=tiny decoder_cross_attention_feature=raw \
  selfattn_lora_r=16 selfattn_lora_alpha=32 \
  r_max=8 lora_alpha=16 \
  virtual_env=$HOME/venv \
  cache_dir=$HOME/.hf_cache \
  output_dir=exp/libri2mix

Just stage 3 (fine-tune) from an existing dump

bash run.sh stage=3 stop_stage=3 \

Tip: the launcher scripts pre-define encoder / decoder / corpus / talker_numbers at the top of each file. Edit those, then run the script — it calls run.sh directly (defaults for all other flags live in run.sh itself); the configurations run sequentially and failures are reported at the end.
