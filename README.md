# Multi-Talker ASR with Large Language Models

This repository contains code for **large language model (LLM)-based multi-talker automatic speech recognition (ASR)** with **serialized output training** on mixture speech.

The implementation is based on the following papers:

- Hao Shi, Yusuke Fujita, Tomoya Mizumoto, Lianbo Liu, Atsushi Kojima, and Yui Sudo,
  **"Serialized Output Prompting for Large Language Model-based Multi-Talker Speech Recognition"**,
  in Proc. IEEE ASRU, 2025 (Accepted).

- Hao Shi, Yuan Gao, Zhaoheng Ni, and Tatsuya Kawahara,
  **"Serialized Speech Information Guidence with Overlapped Encoding Separation for Multi-Speaker Automatic Speech Recognition"**,
  in Proc. IEEE SLT, 2024, pp. 198–204.

If you use this repository in your research, please consider citing these works.

---

## Overview

This project focuses on **multi-talker ASR** using LLMs as the backend decoder. It combines:

- **Serialized Output Training (SOT)** for multi-talker transcriptions, and
- **Serialized CTC training** to better utilize CTC-style supervision in a serialized framework.

A single audio mixture containing *N* overlapping speakers is encoded by a WavLM front-end. An optional separator splits encoder features into *N* per-speaker streams supervised by per-speaker CTC heads. A LLaMA decoder generates all *N* transcriptions as one serialized token sequence, separated by a `<sc>` token. The full training objective is a weighted hybrid of attention cross-entropy on the decoder and per-speaker CTC.

> 📖 **For a visual walkthrough of the architecture, data flow, file map, and every CLI flag, open [`WORKFLOW.html`](WORKFLOW.html) in a browser.**

The current implementation targets **LibriMix** mixtures and supports **2-speaker (2mix)** and **3-speaker (3mix)** settings.

| Family | Sizes | Variants |
|---|---|---|
| LLaMA-3.2 | 1B, 3B | base, Instruct |
| LLaMA-3.1 | 8B | base, Instruct |

(Adjust the exact model names/paths according to your local setup.)

### Datasets

- **LibriMix** — 2-speaker mixtures (`libri2mix`) and 3-speaker mixtures (`libri3mix`), clean and noisy variants.
- Plug in other multi-speaker datasets by following the same serialized-output and serialized-CTC interface.

## Training Modes

The `train_mode` flag selects which loss is active:

| Mode | Active loss | What trains | Typical use |
|---|---|---|---|
| `attention` | CE only | Decoder + adapters | Pure SOT baseline |
| `ctc` | CTC only | Encoder + separator + CTC heads | Pre-train separator before LLM fine-tuning |
| `hybrid` | α·CE + (1-α)·CTC | Everything trainable | Main training recipe |

α is fixed via `ctc_alpha` (default 0.7 in `HybridLoss`).

## Getting Started

### 1. Environment

Python: 3.10.16

```bash
git clone https://github.com/hshi-speech/Multi-talker-ASR-with-LLMs.git
cd Multi-talker-ASR-with-LLMs

# (optional) create and activate a virtual environment
python -m venv venv
source venv/bin/activate

pip install -r requirements.txt
```

> ⚠️ `requirements.txt` was generated by a system-wide `pip freeze` and is missing the core ML deps. At minimum you also need:
>
> ```bash
> pip install torch transformers peft accelerate datasets safetensors \
>             librosa soundfile sentencepiece jiwer wandb hydra-core
> ```

### 2. Prepare the LibriMix dataset

Stage 1 builds a HuggingFace `DatasetDict` from LibriMix's `wav.scp` and `text` files:

```bash
bash run.sh stage=1 stop_stage=1 \
  corpus=libri2mix_clean talker_numbers=2 \
  ... # rest of the flags (see "Run recipes" below)
```

Output goes to `datasets/libri{N}mix_*/`.

### 3. Build the pretrained AED model

Stage 2 combines `microsoft/wavlm-large` with a LLaMA decoder, adds the special tokens (`<bos_prompt>`, `<eos_prompt>`, `<bos_speech>`, `<eos_speech>`, `<bos_response>`, `<eos_response>`, `<sc>`), and saves the initial checkpoint under `dump/<encoder>-<decoder>/`.

```bash
bash run.sh stage=2 stop_stage=2 \
  encoder=wavlm decoder=Llama-3.2-1B \
  talker_numbers=2 instruct=false \
  ...
```

### 4. Train

```bash
bash run.sh stage=3 stop_stage=3 \
  corpus=libri2mix_clean \
  encoder=wavlm decoder=Llama-3.2-1B \
  train_mode=hybrid \
  talker_ctc=true talker_numbers=2 \
  adapter_only_decoder=true \
  encoder_freeze=true decoder_freeze=true \
  partial_others_unfreeze="enc_to_dec_proj" \
  per_device_train_batch_size=8 per_device_eval_batch_size=8 \
  epoch=30 eval_steps=1600 \
  precision=bf16 \
  selfattn_lora_r=16 selfattn_lora_alpha=32 \
  output_dir=exp/libri2mix \
  virtual_env=$HOME/venv \
  cache_dir=$HOME/.hf_cache
```

The output directory is built from the flag values, e.g.
`exp/libri2mix/mode_hybrid-wavlm-Llama-3.2-1B-encoder_freeze-decoder_freeze-adater_decoder-ctc-libri2mix_clean/`.

### 5. Evaluate (attention decoder + WER)

```bash
bash run.sh stage=4 stop_stage=4 \
  # ... same flags that produced output_dir
```

This generates `{validation,test}_label.text`, `{validation,test}_decod.text`, and `{validation,test}_decod.wer` under the output directory.

### 6. CTC-only decoding

```bash
bash run.sh stage=5 stop_stage=5 \
  # ... same flags; uses the per-speaker CTC heads directly
```

### 7. Multi-GPU inference / pseudo-label generation

```bash
bash run.sh stage=6 stop_stage=6 \
  # ... shards eval/train set across GPUs, merges outputs on rank 0
```

## SLURM Submission

Pre-configured templates live in `slurm/`:

```bash
cd slurm

# Generic submitters per LLaMA size
bash submit.sh        # 1B
bash submit_3b.sh
bash submit_8b.sh

# Recipe-specific:
bash sot_submit_{1b,3b,8b}.sh         # SOT only
bash ctc_submit_{1b,3b,8b}.sh         # CTC only
bash crossatt_submit_{1b,3b,8b}.sh    # with cross-attention adapters
bash cross_gate_submit_{1b,3b,8b}.sh  # with gated/LoRA cross-attention
```

Each submitter sets recipe-specific flags at the top of the file and forwards everything else to `run.sh` via `slurm/template.slurm`. Edit the top of the script (encoder, decoder, corpus, talker_numbers) to change the run.

## Key Configuration Flags

The full reference (with default values and effect tables) lives in [`WORKFLOW.html`](WORKFLOW.html). The most commonly-tuned flags:

### Mode & architecture
| Flag | Notes |
|---|---|
| `train_mode` | `attention`, `ctc`, or `hybrid` |
| `talker_ctc` | Enable separator + per-speaker CTC heads |
| `talker_numbers` | 2 or 3 |
| `instruct` | Use Llama-Instruct + prompt-wrapped inputs |
| `adapter_only_decoder` | Inject LoRA into decoder self-attention (merges back after training) |

### LoRA (two independent groups)
| Flag | Default | Where it applies |
|---|---|---|
| `selfattn_lora_r` | 16 | LoRA rank on decoder `k/q/v/o_proj` |
| `selfattn_lora_alpha` | 32 | LoRA alpha (scale = α/r) |
| `selfattn_lora_dropout` | 0.1 | LoRA dropout |
| `r_max` | 16 | Adaptive-rank LoRA inside `adapgatetiny` cross-attention adapter |
| `lora_alpha` | 16 | Cross-attention LoRA alpha |

### Cross-attention adapters
| Flag | Values | Effect |
|---|---|---|
| `decoder_cross_attention` | true/false | Insert per-layer cross-attn adapters into the decoder |
| `decoder_cross_attention_type` | `tiny`, `gatetiny`, `adapgatetiny`, `ctcaware` | Adapter variant |
| `decoder_cross_attention_feature` | `raw`, `sep` | Use raw WavLM features or per-speaker separator features as cross-attention memory |

### Freezing
| Flag | Effect |
|---|---|
| `freeze_encoder` / `freeze_decoder` | Default-freeze the encoder/decoder |
| `freeze_feature_encoder` | Freeze WavLM front-end CNN (default true) |
| `partial_encoder_unfreeze` | Comma list of name substrings to re-enable grad on |
| `partial_decoder_unfreeze` | Same for decoder |
| `partial_others_unfreeze` | Same for non-encoder/decoder params (e.g. `enc_to_dec_proj`) |

### Training
| Flag | Default | Notes |
|---|---|---|
| `epoch` | — | Number of epochs |
| `per_device_train_batch_size` / `per_device_eval_batch_size` | — | Per-GPU batch size |
| `learning_rate` | 3e-5 | Hardcoded in `run.sh` |
| `warmup_steps` | 400 | LR warmup |
| `eval_steps` | — | Evaluate every N steps |
| `save_steps` | 1600 | Checkpoint frequency |
| `precision` | `fp32`, `fp16`, or `bf16` | Mixed-precision mode |
| `seed` | 42 | Random seed |

## Repository Layout

```
finetune_asr.py          stage 3 entry — fine-tuning
inference_asr.py         stage 4/5 entry — single-GPU inference
inference_asr_gpus.py    stage 6 entry — multi-GPU sharded inference
run.sh                   main orchestrator: stages 1-6
WORKFLOW.html            interactive workflow + architecture documentation

models/                  model code
  modeling_speech_encoder_decoder_llama.py  # glue model
  modeling_wavlm.py                         # WavLM encoder
  modeling_llama.py + llama_modules.py      # LLaMA decoder + layers
  separator.py                              # LSTM separator
  ctc.py                                    # CTC head
  losses.py                                 # HybridLoss
  *_crossatt_module.py                      # cross-attention adapter variants
src/                     training infrastructure (args, collator, trainer, loaders)
utils/                   helpers (dataset prep, generation, freeze/unfreeze, WER)
slurm/                   SLURM submit scripts
datasets/                generated by stage 1
dump/                    generated by stage 2
```

For an annotated tree, see [`WORKFLOW.html`](WORKFLOW.html#filemap).
